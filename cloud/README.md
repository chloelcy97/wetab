# 云开发后端

替掉 Supabase 的那一层。数据结构和同步协议跟原来一模一样，
`tally_create / tally_pull / tally_push` 三个函数合成了一个云函数 `tally`，用 `action` 分派。

**为什么换**：云开发走的是 `wx.cloud.callFunction`，不是普通域名请求，
所以完全不碰 ICP 备案。内地主体、香港主体都能用 —— 主体那一关只决定个人还是公司注册，
不再卡后端选型。

> `wx.cloud` 只在小程序运行时里存在。所以这套后端要等小程序的界面层写出来才接得上，
> 现在的网页版还是连 Supabase。两边可以并行跑一段时间，确认无误再断。

---

## 开通（全程在微信开发者工具里，不用命令行）

1. 开发者工具左上角「云开发」→ 开通，环境名随便，记下**环境 ID**
2. 云开发控制台 → 数据库 → 新建三个集合：`ledgers`、`trips`、`entries`
3. 三个集合的**权限都设成「所有用户不可读写」**

   小程序端直接查库会被拒，只有云函数用管理员权限进得去，
   而它每次第一件事就是拿账本码换 ledger id。和原来 Supabase 那套 RLS 全锁死
   加 security definer 函数是同一个模型。

4. 建索引（数据库 → 对应集合 → 索引管理）：

   | 集合 | 字段 | 属性 |
   | --- | --- | --- |
   | `ledgers` | `code` | 唯一 |
   | `trips` | `ledgerId` 升序 + `updatedAt` 升序 | 组合，非唯一 |
   | `entries` | `ledgerId` 升序 + `updatedAt` 升序 | 组合，非唯一 |

   增量拉取全靠后两个索引。不建的话数据一多，`pull` 会慢到超时。

5. 把 `cloud/functions/tally` 整个目录放进小程序项目的云函数目录，
   右键该目录 → **上传并部署：云端安装依赖**

   本机没有 Node 也没关系，依赖是在云端装的。

## 从 Supabase 搬过来

**别急着断 Supabase。** 顺序是先搬、后核对、最后才断。

1. 网页版 →「设置 → 导出账本」，拿到一个 `wetab-YYYY-MM-DD.json`
2. 小程序 →「设置 → 创建账本」，拿到一个新的 12 位账本码
3. 小程序 →「设置 → 导入账本」，选那个 JSON
4. 两边对一下笔数、总额、项目数
5. 都对上了，再在网页版「设置」里断开 Supabase

导入用的是和同步同一套合并规则（按 id 比 `updatedAt`，谁新谁赢），
所以第 3 步做几次都没关系，不会重复也不会覆盖。

其他人各自重复第 3 步之前，先让他们用新账本码「加入账本」，
这样导进去的记录会同步给所有人，不用每个人都导一遍。

## 和 Supabase 版的几处不同

| | Supabase | 云开发 |
| --- | --- | --- |
| 上游 upsert | `on conflict do update` | `doc(_id).set()` |
| 防跨账本覆盖 | SQL 里 `where ledger_id = v_id` | `_id` 拼成 `ledgerId:记录id`，从结构上就串不了 |
| 一次读取上限 | 无 | 100 条，`pullAll()` 里翻页 |
| 时间戳 | `now()`，事务快照一致 | 云函数进来时取一次 `new Date()`，查询钉死在这个上界 |

最后一条不是小事：云开发这几个查询不在一个事务里，
如果先查完再取 `now()` 当 serverTime，落在这中间的写入会被永远跳过 ——
下次带着更晚的 `since` 也拉不到它。所以上界必须先取、并且写进查询条件。

## 没做的部分

云函数写完并单测过了（内存版数据库跑通建账本、250 条分页、增量、软删除、
跨账本隔离、错码拦截、超量保护），但**验的是这个函数自己的逻辑，不是腾讯的实现**。
真机联调要等有 AppID。

界面层还没动。`app.js` 用的是 DOM 和 `innerHTML`，小程序里得换成 WXML + setData，
或者用 Taro 重写。`convert / balances / settlements / personTotals / tripSummary / fmt`
这几个纯计算函数可以原样复制过去。
