# WeTab · 一起记账

几个人一起记账。多币种自动按实时汇率换算成港币 / 英镑 / 人民币，
按分类和行程拆开看，随时知道谁该转给谁多少。没网也能开、也能记。

界面有中文和英文，设置里随时切，只影响你这台设备。

标记是一个斜等号：等号斜过来的两道平行线。既是「两清」也是「平分」，
正好是这个应用在做的唯一一件事。

零构建：不需要 Node、不需要 npm、不需要 `pip install`。只要有 Python 3.8+。

---

## 跑起来

```bash
python3 server.py
```

打开 http://localhost:5173 。首次进入会问你两个名字，可以选空账本或示例数据。

想换端口：

```bash
python3 server.py --port 8080
```

服务只做两件事：托管静态文件，外加一个备用的汇率出口。前端其实直连
frankfurter（那边 CORS 是 `*`），所以线上部署在 GitHub Pages 上不需要任何后端。

### 装到手机主屏

手机和电脑在同一个 Wi-Fi 下，把 `server.py` 里的 `127.0.0.1` 改成 `0.0.0.0`，
然后手机 Safari 打开 `http://<电脑内网 IP>:5173`，「分享 → 加到主屏幕」。
有 manifest 和图标，打开后没有浏览器地址栏，跟原生 app 差不多。

## 它能做什么

**项目（按旅行 / 城市分开算）**
- 每次旅行开一个项目，填上起止日期和当地货币
- 账本顶部一排 chip 切换：全部 / 日常 / 各个项目
- 记账时按日期**自动归类**：日期落在某个项目区间内就自动归过去，会提示你一声
- 在项目里记账时，金额默认用这个项目的当地货币，不用每次改
- 每个项目单独算「谁先垫了多少」，可以只结算这一趟
- 统计页有「按项目」卡片：这趟总共花了多少、每个人各花多少、要转几笔才结清
- 删项目不会丢账，里面的记录会退回「日常」

**成员（2 到 8 人）**
- 设置里随时加人、改名、移除
- 移除是软删除：历史记录里的名字还认得出，只是记新账时不再出现
- 头像是名字的首字母
- 头像色从强调色附近取，色相摆幅 ±65°、饱和度压到 0.34 以内，八个人是一个家族而不是彩虹

**记账**
- 17 种货币输入，输入时实时显示换算成 HKD / GBP / CNY 的结果
- 5 个分类：餐饮、交通、住宿、购物、门票
- **谁付的 + 谁分摊**分开选：勾中的人平摊。全选是 AA，只勾自己是请客，只勾别人就是记在他头上

**算账**
- 余额卡列出每个人「该摊多少」，再给出转账建议
- 每个人算一个净额，全员加起来恒为 0
- 净额化成「谁转给谁多少」的最少笔数建议（贪心，最多 N-1 笔）
- 只有一笔时是个大数字，多笔时是一张清单，点「结算」可以只结其中一笔
- 当前在某个项目里时，只结算这个项目
- 顶部切 HKD / GBP / CNY，全站金额跟着换，包括历史记录

**语言**
- 中文 / English，设置 → 外观里切
- 第一次打开按浏览器语言猜，之后以你选的为准
- 只影响这台设备，不跟账本同步：你看中文、对方看英文，底下是同一笔账
- 日期、星期、月份交给 `Intl` 排，不是自己拼字符串
- 项目名、商家、备注是你写的数据，不翻译

**离线**
- Service worker 缓存全部外壳，断网照样打开
- 离线记的账存在本地，恢复网络后自动补传
- 策略是 stale-while-revalidate：先给缓存（秒开），后台悄悄更新，下次打开就是新版

**统计**
- 按月看总支出、每个人的份额、分类占比排行
- 可以翻到过去的月份
- 下面的「按项目」不受月份影响，看的是每个项目从头到尾的全部花费

**同步（几个人共用一个账本）**
- 一方在「设置 → 创建账本」拿到 12 位账本码，发给其他人，他们选「加入账本」
- 记账、改名、建项目、删除都会自动同步，攒 700ms 一起发，连着改几笔只发一次
- 按条 upsert，不是整包覆盖 —— 几个人同时记账不会互相盖掉
- 删除是软删除，所以对方那边也会消失
- 没网就把改动存在本地，恢复网络后自动补上
- 回到页面时、有网时、每 90 秒各拉一次。记账不需要 websocket
- **显示币种、外观和语言都不同步**：各人看自己习惯的，底下是同一笔账

**备份**
- 「设置 → 导出账本」导出一份 JSON，「导入账本」再读回来
- 导入是**合并**不是覆盖：按 id 比 `updatedAt`，谁新谁赢，内容一样的直接跳过
- 所以导入旧备份不会盖掉现在更新的记录，同一个文件导两次也不会多出东西
- 确认框会先如实报出「补回几笔、更新几笔、几笔保持不动」再动手
- 导入**不读**备份里的账本码。那串码是「连到哪个账本」的钥匙，让它跟着文件走，
  会把人静悄悄换到另一个账本上。要换账本请走「设置 → 加入账本」

**外观**
- 四套配色：钴蓝 / 青瓷 / 黛紫 / 雾灰
- 明暗三档：跟随系统 / 强制浅色 / 强制深色
- 所有配色 × 明暗共 8 种组合都跑过 WCAG AA 校验（正文 4.5:1，三级文字 3.5:1）
- 触屏上输入框强制 16px：iOS Safari 在字号小于 16px 时会自动放大页面且不缩回

**支持开发者（可选）**
- `config.js` 里填上收款页地址（Buy Me a Coffee / Ko-fi / 爱发电 都行），设置里才会出现入口
- 留空则整个入口不显示，别人拿去用不会看到你的收款码
- 插画是原创的极简线稿，`currentColor` 继承主题色，四套配色和明暗都自动适配
- 线宽用 `vector-effect: non-scaling-stroke`，所以 22px 的行内图标和 220px 的主插画是同一种笔触

**汇率**
- 来自欧洲央行（通过 frankfurter.dev），每天首次打开时取一次，之后走本地缓存
- 取不到就退回内置的离线汇率，界面上会明确标出来

## 数据在哪

**没开同步时**：账目只存在浏览器的 `localStorage`（key 是 `wetab.state.v1`），不上传任何地方。

**开了同步之后**：账目存在 Supabase。三张表的 RLS 全部锁死，anon key 碰不到表，
所有读写必须走 `tally_create / tally_pull / tally_push` 三个 security definer 函数，
每个函数第一件事就是拿账本码换 ledger id。所以那串 12 位账本码就是唯一的钥匙，
约 31¹² 种组合猜不出来，但拿到的人就能看账，别公开分享。
本地 `localStorage` 继续当离线缓存用。

## 文件结构

```
index.html                    外壳（在仓库根目录，GitHub Pages 直接托管）
styles.css                    设计系统（四套配色 token、明暗、全部组件）
app.js                        全部逻辑：状态、汇率换算、结算、四个视图、表单、同步、外观、插画
i18n.js                       中英文案 + 语言切换
config.js                     Supabase 连接、汇率地址、收款页地址
favicon.svg                   标签页图标（矢量）
icon-*.png                    主屏图标（斜等号标记）
sprite.svg                    Phosphor 图标合成的 sprite（由 icons/ 重建，不要手改）
icons/                        原始 Phosphor SVG
manifest.webmanifest          PWA 配置
sw.js                         Service worker：离线缓存
server.py                     本地开发服务：静态文件 + /api/rates（线上不需要它）
.claude/launch.json           给 Claude Code 用的启动配置
supabase/schema.sql           建表 + RLS + 三个 RPC 函数，粘进 Supabase SQL Editor 跑
cloud/                        微信云开发后端（小程序用，见 cloud/README.md）
```

品牌标记（斜等号）内联在 `app.js` 的 `brand()` 里，不在 sprite 中，所以重建 sprite 不会动到它。
要加 Phosphor 图标的话，把 SVG 丢进 `icons/`，然后：

```bash
python3 -c "import re,pathlib; d=pathlib.Path('icons'); out=['<svg xmlns=\"http://www.w3.org/2000/svg\" style=\"display:none\">']+[f'<symbol id=\"ph-{f.stem}\" viewBox=\"0 0 256 256\">'+re.sub(r'^<svg[^>]*>|</svg>\s*$','',f.read_text().strip())+'</symbol>' for f in sorted(d.glob('*.svg'))]+['</svg>']; pathlib.Path('sprite.svg').write_text('\n'.join(out))"
```

## 设计上定死的几条

- 每套配色只有一个强调色，不引入第二个装饰色。成员头像色是独立 token（`--member-0` 到 `--member-7`），从强调色绕色相环取，饱和度明度对齐，加到第 8 个人也不会跳出配色体系。
- 配色的对比度不是靠眼睛定的：`--muted` 这类弱化文字最初在四套里都不达标（钴蓝只有 3.57:1），是脚本按 WCAG 阈值自动加深后再复验的。
- 圆角只有四档：卡片 18px、输入 12px、图标底 14px、按钮和胶囊全圆。
- 所有数字用等宽字体 + `tabular-nums`，金额上下对齐、切币种时不跳动。
- 字体全用系统字体栈（iOS 上就是 SF Pro / SF Mono），不加载任何网络字体，首屏没有闪字。
- 明暗默认跟随系统，也可以强制。配色写在 `<html data-palette>`，明暗写在 `data-theme`，互不干扰。
- 动效只有三处：列表首次进场、抽屉弹出、统计条形展开。都受 `prefers-reduced-motion` 控制。列表进场只在首屏跑一次，切币种和增删记录不重播。
- 文案里带参数的串写成函数，不用 `{0}` 占位符：占位符换语言时容易顺序错，函数签名两边不一致会当场报错。

## 微信小程序

后端已经写好了，在 `cloud/`，见 `cloud/README.md`。
选云开发是因为它走 `wx.cloud.callFunction`，不是普通域名请求，完全不碰 ICP 备案 ——
内地主体和香港主体都能用。

注册时要填的几栏：

| 栏位 | 填什么 |
| --- | --- |
| 名称 | WeTab 一起记账 |
| 简介 | 几个人一起记账。多币种按实时汇率换算，按分类和行程拆开看，随时知道谁该转给谁多少。 |
| 服务类目 | 工具 → 效率 |
| 图标 | `icon-512.png` |

简介限 4 到 120 字。名称加了「一起记账」是因为纯英文名过审要额外提供商标材料。

**界面层还没写。** `app.js` 用的是 DOM 和 `innerHTML`，小程序里得换成 WXML + setData，
或者用 Taro 重写。`convert / balances / settlements / personTotals / tripSummary / fmt`
这几个纯计算函数可以原样复制过去，`i18n.js` 也能直接搬。

## 如果之后要搬去别的地方

**做成真正的 App**：现在就是标准的响应式 Web App，用 Capacitor 直接包成 iOS/Android 壳最省事，
`app.js` 一行不用改。

> ⚠️ **多人支持改过数据库结构**（entries 多了 `participants` 和 `to_id`）。
> 升级后要把 `supabase/schema.sql` 重新跑一次 —— 它可以重复执行，旧数据会就地迁移。
> 没跑之前客户端也不会崩（会按老规则还原分摊人），但会弹提示让你去跑。
